# Control-plane example

A copyable layout for a repository that pins agent infrastructure and gates it
in CI.

Files to commit:

- `.gitignore` — the managed infra/also blocks; harness files stay out of git;
- `also.lock` — generated by `also install`, pins content versions and digests;
- `also.policy.yml` — source, executable and size rules plus the governance
  block;
- `also.policy.sig` — detached Ed25519 approvals over the policy bytes;
- `.github/workflows/also.yml` — the CI gate.

The product repository does not commit `.opencode/`, `AGENTS.md`,
`opencode.json`, `.claude/` or `CLAUDE.md`. `audit --ci` fails if any of them is
tracked by git.

## First setup

```sh
also policy keygen --private ~/.also/keys/policy.key --public ~/.also/keys/policy.pub
```

Put the printed public key into `governance.approvers` in `also.policy.yml`,
then trust it locally and sign:

```sh
also policy trust --key "$(cat ~/.also/keys/policy.pub)" --name maintainer
also policy sign --key ~/.also/keys/policy.key
```

Install once, keep the harness files out of git, commit the lock and policy,
and verify:

```sh
also exclude infra for opencode
also exclude you
also install code-review for opencode
also policy verify --ci
also audit --ci
git add .gitignore also.lock also.policy.yml also.policy.sig
```

If the repository owns an `AGENTS.md` or `opencode.json`, install everything
except the managed instructions/settings instead:

```sh
also install code-review for opencode \
  --except instructions --except settings --except mcp
```

## CI

Set `ALSO_POLICY_PUBLIC_KEYS` to the comma-separated base64 public keys of every
approver. The workflow then runs `install --frozen`, `policy verify --ci`,
`audit --ci` and writes an SBOM. The policy cannot trust its own key, so the
secret is the anchor.
